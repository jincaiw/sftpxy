# SFTPxy：如何删除 3 天前上传的文件

SFTPxy 的事件管理器支持通过“数据保留检查（Data retention check）”自动清理过期文件。

在当前 WebAdmin 界面中，数据保留时间单位是 **小时**，不是天。因此，如果你要删除 **3 天前** 的文件，应该填写：

```text
72 小时
```

---

## 1. 目标

实现以下效果：

- 每天或按固定时间执行一次清理
- 删除指定目录下超过 3 天的文件
- 可按用户目录、共享目录或上传目录单独配置

---

## 2. 核心换算

SFTPxy 的保留时间输入框使用小时单位：

```text
3 天 = 3 × 24 = 72 小时
```

所以，删除 3 天前文件时，应设置：

```text
保留时间 = 72
```

---

## 3. 配置步骤

### 第一步：创建动作（Action）

进入：

```text
WebAdmin → Event Manager → Actions
```

新建动作：

- **名称**：`cleanup-files-older-than-3-days`
- **类型**：`数据保留检查`

在数据保留配置中添加一条规则：

- **路径**：要清理的目录
- **小时**：`72`
- **选项**：删除文件（按页面实际选项选择）

例如：

```text
路径：/upload
小时：72
```

如果要清理所有用户目录，可以设置为：

```text
路径：/
小时：72
```

---

### 第二步：创建规则（Rule）

进入：

```text
WebAdmin → Event Manager → Rules
```

新建规则：

- **名称**：`daily-cleanup-3-days`
- **触发器**：`Schedule`
- **状态**：`Enabled`

定时表达式可以设置为每天凌晨执行，例如：

```text
Hour: 3
Day of month: *
Month: *
Day of week: *
```

然后把刚才创建的动作 `cleanup-files-older-than-3-days` 绑定到该规则。

---

## 4. 推荐配置示例

### 方案 A：清理整个用户根目录

```text
Action:
  Type: Data retention check
  Path: /
  Retention: 72

Rule:
  Trigger: Schedule
  Hour: 3
  Day of month: *
  Month: *
  Day of week: *
```

适合：

- 按租户或用户根目录统一清理
- 需要覆盖所有上传内容

---

### 方案 B：只清理上传目录

```text
Action:
  Type: Data retention check
  Path: /upload
  Retention: 72

Rule:
  Trigger: Schedule
  Hour: 3
  Day of month: *
  Month: *
  Day of week: *
```

适合：

- 只清理临时上传区
- 避免误删其它业务目录

---

## 5. 重要注意事项

### 5.1 按什么时间判断

这个功能通常依据文件时间进行判断，常见是：

- 修改时间（mtime）
- 文件系统时间

它**不是专门的“上传时间”字段**。

如果客户端上传时保留了原始文件时间戳，可能会出现：

- 文件刚上传
- 但原始修改时间很早
- 结果被判定为“过期文件”

因此建议先在测试目录验证。

---

### 5.2 先测试再正式启用

建议先用测试路径，比如：

```text
/test-upload
```

确认行为正确后，再切换到正式目录。

---

### 5.3 避免误删共享目录

如果多个用户共用同一目录，务必确认：

- 不会误删共享文件
- 不会删除业务必需文件
- 不会影响正在使用中的数据

---

### 5.4 建议先做备份

正式启用前，建议先备份目录或数据库配置，避免误操作造成数据丢失。

---

## 6. 验证方法

配置完成后，可以这样验证：

1. 在测试目录上传一个文件
2. 手动把文件时间调整到 3 天前以前（测试环境）
3. 执行一次定时规则或手动触发规则
4. 检查文件是否被清理

---

## 7. 总结

如果你要在 SFTPxy 中删除 **3 天前上传的文件**，最关键的是记住：

```text
3 天 = 72 小时
```

最终配置思路是：

- 动作类型：`数据保留检查`
- 保留时间：`72`
- 触发器：`Schedule`
- 执行时间：每天固定时刻

如果只想清理某个目录，优先从单独目录开始配置，例如 `/upload`，更安全。
